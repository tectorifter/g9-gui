# g9-gui — manifest description

This file records the full `description` for the **g9-gui** mod
(`manifest.json`). The manifest's own `description` field is capped at
**80 characters** (a studio rule, so the Mod Manager row and the generator
listing stay readable), so the complete text lives here and the manifest
carries only a short summary.

## Current description (full)

Full-screen modern menu suite for Gen 1, set in Saira -- the closest free match to the FINAL FANTASY XII: THE ZODIAC AGE menu face -- at a 22px body over a 540x360 page the Renderer blits at the WINDOW-FILL scale. Every screen the START menu opens is now that same page at that same size: the START screen, the POKeMON screen, the bag (ITEM), the POKeDEX and the species entry pages it opens, OPTION (including its group sub-pages), the player's trainer card and the MOD MANAGER -- one header, one footer, one type scale, so nothing falls back to the small classic letterbox. The START and POKeMON screens are the two halves of one spread (word-list rail + live party roster with portrait cards, name, HP/MAX figures beside the name, and a gold level with a small "Lv" against the row's right edge, over HP/EXP gauges): the rail omits the POKeMON row and LEFT/RIGHT pages between the two, so the party is always one tap away. A 90%-size Adv.Stats panel is drawn over the menu. Both font weights ship with the mod (SIL OFL 1.1, assets/fonts/), and the identical layout still holds on the engine's own pixel TTF if they cannot be read. The portrait cards come from the g9-battle-sprites pack when that mod is installed -- its front battle sheets for the 'sprites' mode and its own 64x64 party-icon cells for 'icons', each drawn at the pack's own 1:1 pixels, through always-on exports (the 16x16 party-icon atlas is a 4:1 point-sampled copy of those cells, so 'icons' falls back to it -- fitted, and visibly at half the pack's scale -- only when a copy of that mod has no HD cell) -- and the game's own art when it is not (a single log line names the version of that mod it found, so a partial or pre-3.0.8 install is visible instead of just looking broken). A card shows the head space of the pack's own frame at the pack's OWN 1:1 pixels, anchored to the creature -- never zoomed -- so every species keeps the size the pack gives it. Options for the backdrop, embellishments and the portrait presentation. The boot TITLE screen's own menu (CONTINUE / NEW GAME / OPTION / EXIT GAME) and its CONTINUE save-data window are drawn on that same page too -- a rail of rows beside a live SAVE DATA emblem -- and the START screen's SAVE and QUIT prompts are this mod's own modern modals (a save-data card, a YES/NO confirmation, an auto-advancing notice) instead of the classic text boxes, with the one-shot LOAD REPORT modernised as well. The trainer card's badge row now draws the engine's own badge tiles (assets/generated/trainer_card/badges.png) scaled up to fill each slot -- earned badges in their own colours behind a lit gold ring, unearned ones ghosted -- instead of synthetic filled pips with a number. Every piece of the suite now installs and fails INDEPENDENTLY: a sibling file that is missing, fails to compile or throws while it is being built is logged by name and skipped instead of aborting the whole entry chunk (which used to roll every registration back and quietly leave the classic UI in place), a modal whose draw or update throws logs the message once and steps aside instead of blanking the frame, and the boot log always names what installed and whether the modern modals are on. The MOD MANAGER's ERRORS tab (and a mod's own errors page) now carries an EXPORT LOG row: it writes the WHOLE error log -- every per-mod failure and skip reason plus the loader's raw runtime error feed, not just the wrapped display lines -- to g9-gui-error-log.txt at the SAVE FOLDER'S ROOT (the write pins CacheFs' version prefix to the root for that one call and falls back to the engine's version-agnostic mod.cache store, so the same action files the same path on Red and on Gold), and confirms with a SAVED notice on the header. Two screens owned by OTHER mods are re-skinned in place while this mod is installed, without editing either: g9-battle-engine's party-submenu TRAIN editor (a tab strip, the IV/EV nudge row, the six-row STAT/IV/EV/CUR table, an ability panel and a COST/APPLY bar) and g9-battle-sample's OPTIONS BLACKLIST window (the name list with HELD tags, the 3x3 generation grid and RESET). A StateStack.push wrapper dresses each instance's draw and surface only, so the engine's TRAIN logic and the sample's blacklist writes keep running completely untouched on both generations -- each owner screen publishes its own Gen 2 wide-panel contract (drawsWidescreen / panelSize), so the takeover only swaps the surface seam (:uiSize on Gen 1, Shell.gen2Surface on Gold). Every dialogue window in the game is a card of this suite now, too: the engine's own src.render.TextBox -- the box every conversation, sign and in-battle message prints through -- is dressed at that same push wrapper (it identifies itself with isTextBox rather than a screen id), so it keeps its pagination, typewriter, button waits, money box and YES/NO exactly as shipped while only its draw becomes the dark panel with this suite's own Saira for the body and a pulsing down-cursor; it keeps the same 160x144 footprint and never grows the surface -- a bigger UI would drag Renderer:fitScale down (its formula is floor(min(pw/uw, ph/uh)) and the world pass sizes itself from that scale), zooming the map out, and a wide page under the box would also place it differently against the map or battle beneath it. Instead, since 2.2.0 the card is painted in WINDOW space through the engine's render.hud hook, after the frame's composite and at the renderer's own scale, with its fonts rebuilt at that scale by Theme.fontsAt -- so the panel, its hairline border, corner brackets and type are native-resolution rather than a 160x144 bitmap upscaled several times, while the geometry lands in exactly the same screen pixels (same size against the background). Since 2.3.5 that window-space origin also follows the engine's own placement: with the UI centred it is the letterbox origin, and under a DYNAMIC layout, where the engine docks the region to the window's bottom edge, it is the docked origin (uox, vuy + vuh - uih*Uy) -- so DYNAMIC boxes are native-resolution too instead of being drawn into the 160x144 surface and upscaled several times. The MONEY card is never anchored, so it keeps the letterbox spot while the dialogue card docks. The surface card is now only the fail-open fallback for a wide surface or an engine without the hook. Since 2.3.4 the body is the suite's OWN Saira on every engine, drawn by this module at the window's own size (Saira 30 in window space, 10 on the surface) -- the higher-density, resampling-free path; 2.3.3's brief handoff of the body to the host engine's TTF (src.render.Font.draw, which printed gen1recomp's 8px Plain Pixel as an upscaled bitmap) is gone. The body sits at 10 since 2.3.2 (a 7px cap, a touch under the vanilla 8px tile glyph), stepping down to 9 for a wide line that still will not fit, and that body fits MORE of each message per line rather than just smaller type, because the skin re-pages the box at Saira's own width instead of the engine's 18 tile cells: a line the engine broke at 18 glyphs runs to about 29, so the two-line card shows roughly half again as much text. The re-flow copies the engine's own pagination exactly (same \n/\v/\f handling, same soft-wrap on glyph boundaries and last-space preference, same contBefore scroll flags) and is skipped for pause-marker and instant boxes, whose code streams must not move; it also keeps the engine pages and fails open if the engine class or the mod's own font is unavailable. The START screen's header now reads just MENU rather than the player's name, and every footer's arrow hint key is drawn as vector chevrons instead of the missing-glyph box the bundled face used to leave. The Gen 2 (Gold/Silver/Crystal) port is complete. PATCH 2.5.8 fixes a Gen 2 START-menu crash: the portrait handover from g9-battle-sprites is now unwrapped BY SHAPE instead of by Lua type. LÖVE returns a Quad as USERDATA, but the old check only pulled the per-cell frame out of that mod's wrapper table when the wrapper's `full` field was itself a table -- so on a real boot the wrapper TABLE travelled on to love.graphics.draw, which read it as the x coordinate and raised `bad argument #2 to 'draw' (number expected, got table)` the moment the Gen 2 START screen drew its party roster (whose portrait mode always resolves through the icon export). Quads are now recognised by shape (anything answering getViewport), so an unwrapped Quad, a Quad wrapped in the sprites mod's table, and an older copy's bare Quad are all accepted, and the harness now hands quads back as real userdata so this class of bug reproduces there instead of only in-game. PATCH 2.6.3 fixes the party portrait crops for BIG sprites. The card has drawn the head space of the pack's trimmed front frame since 3.0.8, but that bake was the WHOLE ANIMATION's union box at 1:1, and frame 1 of a big sheet sits far below that box's top (DRAGONITE's Mega frame has 51 spare rows; ETERNATUS' frame 1 is a 90x86 content box at y=4 inside a 111x102 union), so a card anchored to the top landed on transparent rows -- an EMPTY card for Mega Dragonite and a mis-placed crop for Eternatus, while small species had so few spare rows that they looked fine. Two things changed. (1) g9-battle-sprites 3.1.2 bakes frame 1 ALONE, trimmed to itself, and answers the frame's own content box as a fourth value, so the card's picture IS the creature. (2) This mod's crop, ui/portraits.lua's drawHeadSpace, anchors to that box with a rule built for a portrait rather than a fixed window: a frame that fits the card is drawn 1:1 as before; a frame whose HEAD would overflow the card is stepped down by an INTEGER divisor (so pixel edges stay hard) until 45% of it -- the head, the most iconic part -- fills the card's height, with a 2x-card width safety valve so a wide-but-short creature is not needlessly halved; nothing is ever zoomed. A frame may crop the creature's sides, which is correct for a head portrait. With an older sprites pack (no box on frontArt) the card keeps the previous 8%-down best-effort window, which cannot be right for a union bake, and one log line names the version to update. The wrap also raises `pokemon.move_learned` and stamps the new slot's `maxPp` the way the engine's own Gold forget arm does, so a mod counting learned moves (g9-evolutions, the battle scene) sees the four-slot case too. Gold's two extra HMs (WATERFALL, WHIRLPOOL) are refused by the page itself in this flow, exactly as the engine's `Game2` refuses the cart's five. Gen 1 is untouched -- its engine already pushes the screen this suite takes over.

Since 3.3.0 the party roster's ICON portraits can ANIMATE. The new PORTRAIT ANIMATION row (OFF by default, offered only while PARTY PORTRAITS is ICONS -- the schema's own `visible_if` keeps it off the manager's list otherwise, and the list rebuilds live when that row is stepped) steps the pack's two frames of each icon once a second, one full second per frame, on the mod's own wall clock rather than the sprites mod's SPRITE FPS. It applies to the HD cell and to the fitted 16x16 fallback alike, and to the game's own icon sheets when no sprites mod is installed (their second frame is stacked under the first); OFF holds the resting frame, and an egg -- a single picture -- never animates. The chosen frame is passed through to g9-battle-sprites' `iconArtHD` / `iconArt16` (3.4.0+), so each portrait crops to the frame it is actually holding instead of one that jitters with the other mod's clock.

Since 3.3.1 the ICON portraits ACTUALLY MOVE. 3.3.0 asked the sprites mod for the frame it was holding AND cropped to that frame's own content box -- and the pack's whole icon animation is the creature bobbing two pixels UP on frame 1 (frame 1's content box is exactly frame 0's, two rows higher, and the two frames are otherwise pixel-identical: measured against the pack, every icon, both atlases, the opaque boxes differ by `(0, -2)` and the frames' content is identical). Cropping to each frame's own box therefore followed the bob and cancelled it exactly: the two seconds rendered PIXEL-IDENTICAL cards (a card-pixel difference of 0), which is the reported "the icons are a good size but never move". An ANIMATED card now crops to the two frames' TRAVEL box -- their union, the higher of the two content boxes -- which stays fixed in the atlas cell, so the creature's own two-pixel bob is what moves inside the card (a card-pixel difference of ~17-40); neither frame is clipped at the top. A still card (the row OFF, or any BATTLE SPRITES portrait) is unchanged: it keeps the resting frame's own box. The clock, the frame pass-through, the schema and every caller are untouched.
